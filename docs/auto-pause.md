# 離席・画面ロック時の自動停止

設定の「離席・画面ロック時にタイマーを止める」は既定で OFF。旧版の設定ファイルを読み込んだ場合も OFF になり、既存の作業時間などは保持する。設定から ON にすると以下の動作が有効になる。明示的に ON にした設定は再起動後も保持する。

- 作業・予兆中に5分間マウス／キーボード入力がなければ、フェーズと残り秒を保持して停止する。最初の5分は作業時間として進む。
- 休憩・雨上がりは入力がなくても進む。画面ロック・ユーザー切替は全フェーズで停止する。
- 入力再開・ロック解除後、作業中なら離席条件も解消したときに自動再開する。手動で一時停止していた場合は停止を保持する。
- 自動停止中は雨・音・HUDを退避し、Esc のグローバル登録を外す。トレイのツールチップに「自動停止（離席）」または「自動停止（画面ロック）」を表示する。
- 読書・動画視聴など入力を伴わない作業では、設定を OFF にする。OFF は即時に自動停止だけを解除し、手動停止は保持する。

Rust スケジューラが1秒ごとに観測するため、入力・ロック変化の反映には通常最大約1秒かかる。取得するのは入力からの経過時間とセッション状態だけで、キー・マウス操作の内容は取得・保存しない。観測失敗だけで既知の自動停止を解除しない。スリープからの復帰時に未処理 tick を連続消化しない。

Windows は `GetLastInputInfo` と `WTSQuerySessionInformationW(WTSSessionInfoEx)`、macOS は CoreGraphics の最終入力経過時間とセッション辞書を使う。macOS の画面ロック判定には Quartz の補助キー `CGSSessionScreenIsLocked` を使うため、OS更新時には以下の実機確認も行う。Linux は対応OS外で、この検知は無効。

## 自動検証

```sh
cargo test --locked --manifest-path crates/core/Cargo.toml
cargo test --locked --manifest-path src-tauri/Cargo.toml -- --skip commands::tests::capture_returns_jpeg_data_url
pnpm run check
pnpm run build
```

コアの自動停止テストは実時間を待たずに、5分の境界・入力再開・各フェーズのロック・手動停止の保持・取得失敗・設定 OFF を確認する。シェルのテストは旧設定の互換性、OFF の永続化、スリープ後の tick を確認する。キャプチャ疎通テストは実ディスプレイが必要なので、上のヘッドレス向けコマンドでは除外する。

## macOS／Windows の実機確認

1. 自動停止を ON、作業時間を20分にし、5分以上入力せず待つ。トレイが「自動停止（離席）」となり、HUDが隠れ、残り時間が止まる。入力すると同じ残り時間から再開する。
2. 作業・予兆・休憩・雨上がりの各フェーズで画面をロックし、10秒以上待って解除する。ロック中はフェーズと残り時間が進まず、解除後に同じフェーズへ戻る。雨上がりの虹は最初から再生されず、残り時間に合った位置に戻る。
3. 手動で一時停止してからロック・解除する。タイマーが勝手に再開しないことを確認する。
4. 休憩中は入力がなくても休憩時間が進むことを確認する。
5. 自動停止中に設定を OFF にする。手動停止していなければ再開し、設定の再読込後も OFF を保持する。
6. PC をスリープ・復帰する。復帰直後にタイマーが一気に進まないことを確認する。ユーザー切替／リモートセッションの切断・再接続でも、非アクティブなセッション中に時間が進まないことを確認する。
